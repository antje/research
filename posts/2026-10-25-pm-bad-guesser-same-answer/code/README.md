# The acceptance rule, run millions of times against Qwen3-8B on a B200

Terms: the post's guesser is what vLLM, the papers and this code call the draft model or drafter (it proposes tokens), and the target is the big model that checks them.

The post says speculative decoding's checker makes the output distribution exactly the target's for any guesser, however bad: keep a guess x with probability min(1, p(x) / q(x)), otherwise replace it with a draw from max(0, p − q) normalized, and the chance of ending on any token is p(x). The draft's quality sets only how many guesses survive (the overlap, the sum of min(p, q)). Every rule that keeps more guesses than that changes the distribution, and the only gap left in the exact rule is floating-point arithmetic. This code puts each of those sentences on hardware with a real model's distributions, vLLM's own kernels, and vLLM serving, and it also shows where "exact" stops: the distribution, not the exact tokens of a greedy answer.

## What it measures

The target p is Qwen3-8B's next-token distribution at six fixed prefixes (one forward pass each with transformers, bf16 weights), computed as vLLM computes it: the bf16 output head's logits widened to float32, softmax at temperature 1 over the 151,936-token vocabulary. The prefixes span entropies from 0 nats ("import numpy as", where " np" has all the mass) to 5.2 nats ("Once upon a time, there was a"). No second model is on the host, so drafters q are built from the same logits: the target itself, flatter versions (temperature 2 and 4), a sharper one (temperature 0.5), the target with its top token removed, a one-hot guess on the top token (what an n-gram or greedy drafter hands vLLM), a one-hot on a random token, and the uniform distribution.

Every run is 2^24 guesses (16,777,216). Draws from q and from the replacement distribution use an inverse cumulative sum in float64 (exact to far below the sampling noise), so the only float32 arithmetic in the loop is the rule's own test, written as vLLM writes it: p(x) / q(x) >= u with u a float64 uniform. Every probability vector is checked to sum to 1 before the rule sees it. Two statistics per histogram: the total-variation distance (TV) to p (half the sum of absolute differences, the most any event's probability moved) and Pearson's chi-square per degree of freedom over the tokens expected 25 or more times, the rest pooled (about 1 for a sample of p, growing with the draw count for anything else). The "floor" is the same statistic for 2^24 draws from p itself, so a reader can tell sampling noise from a real gap.

- **Table 1, drafters of every quality.** Every drafter at every prefix: predicted acceptance (the overlap) next to the measured one, the histogram's distance to p next to the floor.
- **Table 2, four plausible wrong rules**, at the temperature-2 drafter: keep if p >= q else sample the target afresh, keep if the guess is the target's top token, keep if p(guess) > 0.05 (the shape of Medusa's typical acceptance with a hard threshold), and Leviathan's lenience with l = 0.5 (compare p against 0.5 q). Each rule's output distribution is also computed in closed form, so the measured distance has a prediction next to it, and the largest ratio of output to target probability is checked against the lenient rule's promised bound of 1 / l.
- **Table 3, the numerics gap.** Three versions of the same target: the float32 head's softmax (the same final hidden state through the output head in float32), vLLM's path (bf16 head, float32 softmax), and that softmax stored in bf16. Rounding a probability vector to bf16 breaks its sum (0.5, 0.3, 0.2 rounds to a vector summing to 1.0009765625, and Qwen3-8B's rounded vectors sum to 0.9991 to 1.0019), so each version, and the drafter built from it, is renormalized in float32 and used that way in the keep test, the refill, the sampler and the distances. The rule runs on each, and its histogram is set against the version it was given and against the float32 reference. Then the rule's own arithmetic: the same guesses and the same uniforms through float32 and float64, counting how many keep decisions and how many outputs differ.
- **Table 4, vLLM's kernels.** `rejection_sample` from `vllm/v1/sample/rejection_sampler.py` (the Triton kernels behind every speculative-decoding step vLLM serves), called as the engine calls it: one draft token per row, 8,192 rows per call, 2^23 draws per drafter, with draft probabilities and on the no-draft-probabilities path the n-gram and greedy drafters take (draft probability set to 1 inside the kernel, the drafted token masked out of the replacement). Penalties are off at this level.
- **Table 5, serving, with and without penalties.** vLLM serving Qwen3-8B with its n-gram drafter (3 draft tokens, lookup of the last 2 to 4 tokens) against five plain engines, each with its own sampler seed, temperature 1, 16,384 samples per prompt on two prompts that repeat themselves so the drafter fires. Each engine serves three sets: no penalties, a mild repetition and presence penalty (1.05 and 0.1), and a strong one (1.3 and 0.5). A repetition penalty divides the score of every token already in the text, and a presence penalty subtracts a fixed amount from every token already generated, so at a guessed position the checker must count the earlier guesses as written. vLLM's `RejectionSampler` does that before it calls the kernel. The n-gram drafter copies tokens already in the text, the exact tokens a repetition penalty pushes down, so the strong set throws out nearly every guess (it tests the refill) and the mild set keeps a third of them (it tests the keep path). The first generated token is never a guess, so it is a control. Each engine, drafted or plain, is set against a pool of four plain engines it is not part of, with the TV and a two-sample chi-square per degree of freedom and its p-value (the chance of a gap at least that large if both samples share one distribution).
- **Table 6, greedy decoding.** Temperature 0 (always the top token), 256 prompts, 128 tokens each, every prompt in one batch, with and without the n-gram drafter, and four more plain engines as a control. For every prompt whose answer differs: the first position where it differs, and the gap there between the top two tokens' log-probabilities (which equals the gap between their logits). The checking pass scores four positions per request where plain decoding scores one, so its kernels see other shapes and round differently, and vLLM's documentation lists batch size as a source of variation in output probabilities.

## What one run showed

Numbers below are from one run on one B200 ([`results/b200-same-answer.md`](results/b200-same-answer.md)). The second run ([`results/b200-run2-same-answer.md`](results/b200-run2-same-answer.md), the other GPU, other seeds) agrees on every row within its noise, and its greedy table is identical to the first run's.

- **Every drafter gave the target's histogram.** Across 48 drafter-prefix pairs the distance to p sat on the floor (for "My favorite color is": 0.370% to 0.385% against a floor of 0.389%) and chi-square per degree of freedom stayed between 0.83 and 1.22 on the five prefixes with any entropy (on "import numpy as", where one token holds all the mass and the statistic has almost no bins, it reads 0.56 to 1.77). Meanwhile acceptance ran the whole range and landed on the overlap every time: 1.000 for the target itself, 0.6395 predicted and 0.6396 measured at temperature 2 on "The number I am thinking of is", 0.2877 and 0.2875 for the one-hot on its top token, 0.0008 for the uniform drafter, 0.0000 for a one-hot on a random token.
- **Every wrong rule moved it, by the closed-form amount.** On "The number I am thinking of is" with the temperature-2 drafter: keep-if-p-at-least-q moved 7.86% of the probability mass (7.87% predicted), keep-the-top-token 10.04% (10.03%), the 0.05 threshold 7.89% (7.87%), lenience at 0.5 8.09% (8.08%), against a floor of 0.036%, and chi-square per degree of freedom 5,460 to 6,350 against 1.2 for the exact rule on the same inputs. The lenient rule's largest gain in closed form is 2.00, its promised bound, and the run reads it at 2.24 to 2.28 with about 10% of sampling noise on the tokens that set it.
- **The numerics gap is the bf16 head, not the rule.** With every vector renormalized, vLLM's bf16-head target differs from the float32-head target by 0.70% ("The number I am thinking of is") to 1.83% ("My favorite color is") of total variation, 0.000% at the zero-entropy prefix, and storing the probabilities in bf16 adds little (0.72% to 1.79%). The rule on each version reproduces that version to the floor. Its own arithmetic in float32 against float64 changed 0 of 16,777,216 keep decisions at every prefix on vLLM's path (1 on one bf16-stored row) and 0 to 9 outputs (the replacement draw's cumulative sum).
- **vLLM's kernels do the same.** Through `rejection_sample`, 2^23 draws per drafter: acceptance 0.6396 at temperature 2 (0.6395 predicted), 0.2878 for the one-hot guess handed over as probabilities and through the no-draft-probabilities path (0.2877), 0.0008 for the uniform drafter. Every histogram sat near its floor, with chi-square per degree of freedom 0.74 to 1.05, the bonus-token column consistent on every row.
- **vLLM serving does too, penalties included.** The drafted engine kept 59.9% of its guessed tokens without penalties, 34.4% with the mild penalty, and 162 of 69,969 with the strong one, so the checker fired in every set and the penalty reached it. Across the 16 rows with any degrees of freedom, the drafted engine's p-values ran from 0.03 to 0.89, with 2 under 0.05 where chance alone gives about 0.8 (in the second run 0.12 to 0.94, none under 0.05). A first version of this table set the drafted engine against each plain engine one by one and read as "drafted sits above the plain spread". Those five distances all share the drafted sample, so they move together, and they sat above the spread at the first token too, which no guess touches.
- **Greedy answers are not bit-for-bit the same.** With the n-gram drafter on, 134 of 256 greedy answers differed from plain decoding somewhere in their 128 tokens, while the four plain control engines matched plain engine 1 on all 256. Every first difference sat at a near tie: the top two tokens' log-probabilities were equal in bf16 at 61 of them and 0.125 to 0.5 apart at the rest, a gap that 1.8% to 13% of all positions show. Where two tokens tie to the last bit, the checking pass's other rounding can pick the other one, and the answers part from there. The guarantee covers the distribution of sampled answers. It does not make one greedy answer bit-for-bit the same.

## Run it

On a Blackwell GPU with a python that has torch 2.13, transformers 5.17 and vLLM 0.31, and Qwen/Qwen3-8B in the Hugging Face cache:

```bash
cd code
CUDA_VISIBLE_DEVICES=0 python -m bad_guesser --quick      # two prefixes, 2^20 draws, no serving run: under a minute
CUDA_VISIBLE_DEVICES=0 python -m bad_guesser              # the full run, about 8.5 minutes (seven of them the six vLLM engines)
uv run --extra gpu pytest -q                              # the A, B, C example and the serving statistics anywhere, the rule, the kernels and the model on a GPU
```

`--draws` and `--kernel-draws` set the log2 of the draws (24 and 23 by default), `--served` the samples per prompt and set (16,384, and 0 skips the sampled sets), `--greedy` the greedy prompts (256, and 0 skips them), `--seed` the generator seed. The script prints the results file and writes `results/<name>.md` and `.json` (the JSON keeps every serving histogram).

## Where the numbers come from

[`results/b200-same-answer.md`](results/b200-same-answer.md) is the run on GPU 0 with seed 0 (engine seeds 1 to 6), [`results/b200-run2-same-answer.md`](results/b200-run2-same-answer.md) the run on GPU 1 with seed 1 (engine seeds 11 to 16). Each ends in a Conditions line (driver, CUDA, torch, transformers and vLLM versions, what was counted, draw counts, seeds, other processes on the GPU). Nothing is timed: these are counts, and clocks do not enter.
