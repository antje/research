# The acceptance rule, run millions of times against Qwen3-8B on a B200

The post says speculative decoding's verifier makes the output distribution exactly the target model's for any draft, however bad: keep a guess x with probability min(1, p(x) / q(x)), otherwise replace it with a draw from max(0, p − q) normalized, and the chance of ending on any token is p(x). The draft's quality sets only how many guesses survive (the overlap, the sum of min(p, q)). Every rule that keeps more guesses than that changes the distribution, and the only gap left in the exact rule is floating-point arithmetic. This code puts each of those sentences on hardware with a real model's distributions, vLLM's own kernels, and vLLM serving.

## What it measures

The target p is Qwen3-8B's next-token distribution at six fixed prefixes (one forward pass each with transformers, bf16 weights), computed as vLLM computes it: the bf16 output head's logits widened to float32, softmax at temperature 1 over the 151,936-token vocabulary. The prefixes span entropies from 0 nats ("import numpy as", where " np" has all the mass) to 5.2 nats ("Once upon a time, there was a"). No second model is on the host, so drafters q are built from the same logits: the target itself, flatter versions (temperature 2 and 4), a sharper one (temperature 0.5), the target with its top token removed, a one-hot guess on the top token (what an n-gram or greedy drafter hands vLLM), a one-hot on a random token, and the uniform distribution.

Every run is 2^24 guesses (16,777,216). Draws from q and from the replacement distribution use an inverse cumulative sum in float64 (exact to far below the sampling noise), so the only float32 arithmetic in the loop is the rule's own test, written as vLLM writes it: p(x) / q(x) >= u with u a float64 uniform. Two statistics per histogram: the total-variation distance to p (half the sum of absolute differences, the most any event's probability moved) and Pearson's chi-square per degree of freedom over the tokens expected 25 or more times, the rest pooled (about 1 for a sample of p, growing with the draw count for anything else). The "floor" is the same statistic for 2^24 draws from p itself, so a reader can tell sampling noise from a real gap.

- **Table 1, drafters of every quality.** Every drafter at every prefix: predicted acceptance (the overlap) next to the measured one, the histogram's distance to p next to the floor.
- **Table 2, four plausible wrong rules**, at the temperature-2 drafter: keep if p >= q else sample the target afresh; keep if the guess is the target's top token; keep if p(guess) > 0.05 (the shape of Medusa's typical acceptance with a hard threshold); and Leviathan's lenience with l = 0.5 (compare p against 0.5 q). Each rule's output distribution is also computed in closed form, so the measured distance has a prediction next to it, and the largest ratio of output to target probability is checked against the lenient rule's promised bound of 1 / l.
- **Table 3, the numerics gap.** Three versions of the same target: the float32 head's softmax (the same final hidden state through the output head in float32), vLLM's path (bf16 head, float32 softmax), and that softmax stored in bf16. The rule runs on each; its histogram is set against the version it was given and against the float32 reference. Then the rule's own arithmetic: the same guesses and the same uniforms through float32 and float64, counting how many keep decisions and how many outputs differ.
- **Table 4, vLLM's kernels.** `rejection_sample` from `vllm/v1/sample/rejection_sampler.py` (the Triton kernels behind every speculative-decoding step vLLM serves), called as the engine calls it: one draft token per row, 8,192 rows per call, 2^23 draws per drafter, with draft probabilities and on the no-draft-probabilities path the n-gram and greedy drafters take (draft probability set to 1 inside the kernel, the drafted token masked out of the replacement).
- **Table 5, serving.** vLLM serving Qwen3-8B with its n-gram drafter (3 draft tokens, lookup of the last 2 to 4 tokens) against the same engine without one, temperature 1, 32,768 samples per prompt on two prompts that repeat themselves so the drafter fires, each engine with its own sampler seed. The first generated token is sampled from the prefill logits and is never a draft, so it is a control; tokens two and three are the first positions a verified draft can fill. A second plain run gives the floor, and vLLM's speculative-decoding counters show the drafts were really verified.

## What one run showed

Numbers below are from one run on one B200 ([`results/b200-same-answer.md`](results/b200-same-answer.md)); the second run ([`results/b200-run2-same-answer.md`](results/b200-run2-same-answer.md), the other GPU, other seeds) agrees on every row.

- **Every drafter gave the target's histogram.** Across 48 drafter-prefix pairs the distance to p sat on the floor (for "My favorite color is": 0.370% to 0.385% against a floor of 0.389%; for "Once upon a time, there was a": 0.551% to 0.566% against 0.566%) and chi-square per degree of freedom stayed between 0.83 and 1.22 on the five prefixes with any entropy (on "import numpy as", where one token holds all the mass and the statistic has almost no bins, it reads 0.56 to 1.77). Meanwhile acceptance ran the whole range and landed on the overlap every time: 1.000 for the target itself, 0.6395 predicted and 0.6396 measured at temperature 2 on "The number I am thinking of is", 0.2877 and 0.2875 for the one-hot on its top token, 0.0008 for the uniform drafter, 0.0000 for a one-hot on a random token. A guesser that is wrong almost every time still left the model's answer alone.
- **Every wrong rule moved it, by exactly the closed-form amount.** On "The number I am thinking of is" with the temperature-2 drafter: keep-if-p-at-least-q moved 7.86% of the probability mass (7.87% predicted), keep-the-top-token 10.04% (10.03%), the 0.05 threshold 7.89% (7.87%), lenience at 0.5 8.09% (8.08%), against a floor of 0.036%; chi-square per degree of freedom 5,460 to 6,350 against 1.2 for the exact rule on the same inputs. The lenient rule's largest gain in closed form is 2.00, its promised bound; the run reads it at 2.24 to 2.28 with about 10% of sampling noise on the tokens that set it.
- **The numerics gap is the bf16 head, not the rule.** The rule's arithmetic in float32 against float64 changed 0 of 16,777,216 keep decisions at every prefix and 0 to 9 of 16,777,216 outputs (the replacement draw's cumulative sum rounding). What does move the distribution is the output head: vLLM's bf16-head target differs from the float32-head target by 0.70% ("The number I am thinking of is") to 1.83% ("My favorite color is") of total variation, 0.000% at the zero-entropy prefix, and the rule on the bf16 target reproduces that target to the floor (0.033% against 0.036%) while sitting 0.71% from the float32 one. Plain sampling without a drafter sees the same 0.7 to 1.8%: the gap belongs to the model's head, and the verifier adds nothing to it.
- **vLLM's kernels do the same.** Through `rejection_sample`, 2^23 draws per drafter: acceptance 0.6396 at temperature 2 (0.6395 predicted), 0.2876 and 0.2875 for the one-hot guess handed over as probabilities and through the no-draft-probabilities path (0.2877), 0.0008 for the uniform drafter; every histogram within the floor (0.030% to 0.047% against 0.035% on "The number I am thinking of is", 0.197% to 0.215% against 0.219% on the letter prefix), chi-square per degree of freedom 0.90 to 1.17, the bonus-token column consistent on every row.
- **vLLM serving does too.** With the n-gram drafter on, the engine made 65,505 drafts of 3 tokens and kept 60.0% of the drafted tokens, and the histograms of the first drafted positions sat on the floor set by two plain runs: at the second token of the cat-and-mat prompt the drafted engine was 2.02% from plain run 1 where plain run 2 was 2.08% from it, at the third 4.20% against 4.13%; on the colors prompt 0.96% against 1.30% and 2.92% against 2.93%. The first token, never a draft, agreed to 0.01%. (An earlier version of this check let all three engines use vLLM's default sampler seed, and the two plain runs reproduced each other bit for bit, a floor of 0.000% that measured nothing. Each engine now gets its own seed.)

## Run it

On a Blackwell GPU with a python that has torch 2.13, transformers 5.17 and vLLM 0.31, and Qwen/Qwen3-8B in the Hugging Face cache:

```bash
cd code
CUDA_VISIBLE_DEVICES=0 python -m bad_guesser --quick      # two prefixes, 2^20 draws, no serving run: under a minute
CUDA_VISIBLE_DEVICES=0 python -m bad_guesser              # the full run, about four minutes (three of them the three vLLM engines)
uv run --extra gpu pytest -q                              # the walk-in anywhere; the rule, the kernels and the model on a GPU
```

`--draws` and `--kernel-draws` set the log2 of the draws (24 and 23 by default), `--served` the samples per prompt (32,768; 0 skips the engines), `--seed` the generator seed. The script prints the results file and writes `results/<name>.md` and `.json`.

## Where the numbers come from

[`results/b200-same-answer.md`](results/b200-same-answer.md) is the run on GPU 0 with seed 0, [`results/b200-run2-same-answer.md`](results/b200-run2-same-answer.md) the run on GPU 1 with seed 1. Each ends in a Conditions line (driver, CUDA, torch, transformers and vLLM versions, what was counted, draw counts, seeds, other processes on the GPU). Nothing is timed: these are counts, and clocks do not enter.

## Files

- [`src/bad_guesser/walkin.py`](src/bad_guesser/walkin.py): the post's three-token walk-in and the closed forms, in plain Python.
- [`src/bad_guesser/rule.py`](src/bad_guesser/rule.py): the exact rule, the lenient one and the three wrong ones in torch, the drafters, the closed-form predictions, the statistics.
- [`src/bad_guesser/target.py`](src/bad_guesser/target.py): Qwen3-8B's next-token logits at the prefixes through the bf16 head and the float32 head.
- [`src/bad_guesser/vllm_kernel.py`](src/bad_guesser/vllm_kernel.py): vLLM's `rejection_sample` on the same inputs.
- [`src/bad_guesser/served.py`](src/bad_guesser/served.py): one vLLM engine per subprocess, with and without the n-gram drafter, and its counters.
- [`tests/`](tests/): the walk-in (anywhere), the rule against its closed forms on a small vocabulary (any torch device), vLLM's kernels against the rule and the model's prefixes (on the GPU).
